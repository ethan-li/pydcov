# Generic Executable Detection

## Overview

The `_find_executables` method in `IncrementalCoverageManager` has been enhanced to be completely generic and project-agnostic. Instead of relying on hardcoded executable names and directory structures, it now uses multiple intelligent strategies to automatically detect executables in any CMake build directory.

## Problem Solved

**Before**: The method was hardcoded to look for specific executables (`algorithm_cli`, `statistics_cli`, `pydcov`) in specific directory structures (`examples/algorithm/app`, `examples/statistics/app`), making it dependent on the current test project structure.

**After**: The method now uses three complementary strategies to generically detect executables from any CMake build directory structure.

## Detection Strategies

### 1. CMake Target Analysis (`_find_executables_from_cmake_targets`)

Analyzes the `CMakeFiles/TargetDirectories.txt` file generated by CMake to identify executable targets:

- Parses target directory paths like `/path/to/build/examples/algorithm/app/CMakeFiles/algorithm_cli.dir`
- Extracts target names (e.g., `algorithm_cli`) from the `.dir` suffix
- Filters out system targets (`test`, `install`, `clean`, etc.)
- Locates the actual executable files in the build directory
- Verifies files are executable and not CMake temporary files

### 2. Make Target Query (`_find_executables_from_make_targets`)

Queries the build system using `make help` to discover available targets:

- Executes `make help` in the build directory
- Parses output format: `... target_name (description)`
- Filters out system targets (`all`, `clean`, `install`, etc.)
- Searches for executable files matching target names
- Validates files are executable and not in CMakeFiles directories

### 3. Intelligent Filesystem Scan (`_find_executables_from_filesystem`)

Performs a smart filesystem scan as a fallback:

- **Pattern-based search**: Looks for common executable patterns:
  - `*_cli` (command-line interfaces)
  - `*_app` (applications)
  - `*_test` (test executables)
  - `*_main` (main programs)
  - `*_demo` (demonstration programs)
  - `*_example` (example programs)

- **Broad search fallback**: If no pattern matches found, scans all files
- **Intelligent filtering**: Excludes:
  - CMake temporary files and directories
  - Non-executable files
  - Files with non-executable extensions (`.txt`, `.cmake`, `.log`, `.json`, `.xml`, `.a`, `.so`, `.dylib`, `.o`, `.obj`, `.gcno`, `.gcda`, `.profraw`, `.profdata`)
  - Known build artifacts (`Makefile`, `cmake_install.cmake`)

## Strategy Priority

The method uses a cascading approach:

1. **Primary**: CMake target analysis (most reliable)
2. **Secondary**: Make target query (good fallback)
3. **Tertiary**: Filesystem scan (comprehensive fallback)

If the primary strategy finds executables, the others are skipped for efficiency. This ensures the most reliable method is used when available.

## Benefits

### 1. **Project Agnostic**
- Works with any CMake-based C/C++ project
- No hardcoded executable names or directory structures
- Automatically adapts to different project layouts

### 2. **Robust Detection**
- Multiple complementary strategies ensure high success rate
- Graceful fallback when CMake metadata is unavailable
- Intelligent filtering prevents false positives

### 3. **Maintainable**
- No need to update code when project structure changes
- Self-discovering based on build system configuration
- Reduces maintenance burden for different projects

### 4. **Comprehensive**
- Finds executables regardless of naming conventions
- Works with nested directory structures
- Handles both simple and complex project layouts

## Usage Example

```python
from pydcov.core.incremental_coverage import IncrementalCoverageManager
from pathlib import Path

# Works with any CMake build directory
manager = IncrementalCoverageManager(Path('/path/to/any/cmake/build'))

# Automatically discovers all executables
executables = manager._find_executables()

for exe in executables:
    print(f"Found executable: {exe}")
```

The change is fully backward compatible:
- Existing functionality is preserved

- No changes required to calling code

## Performance

- **Efficient**: Primary strategy (CMake targets) is fastest
- **Cached**: Results are computed once per instance
- **Filtered**: Smart filtering reduces unnecessary file system operations
- **Timeout protected**: Make commands have timeout protection

This enhancement makes the coverage system truly generic and suitable for use with any CMake-based C/C++ project, eliminating the dependency on specific project structures while maintaining full functionality.
